# ADR-005 — Pre-wave backup enabling live rollback restore

Status: accepted (ACR-005), implemented by T-011 (eos) and T-015 (srlinux,
proven live) in `roles/live_guard`.

## Context
`rollback.yml` restores live waves only via a fail-closed assert: no backup
source exists yet. A live wave without restore is a write without an undo.

## Proposal
Before any live wave: fetch `show running-config` per host into
`reports/backups/<host>-<wave>.cfg` (Vault credentials, masked logs), then
deploy. Rollback replays the backup when post-check fails. Drift fixtures
gain a backup-shaped snapshot for CI.

## Cost
One backup role + rollback logic + backup retention note. No model change.

## Activation
Accept only together with a live lab (image procurement first, per ACR-003).

## Implementation note (T-011)
Deviation from the proposal: backups are written to
`~/.netaut/backups/<host>-<wave>.cfg`, not `reports/backups/`. A running-config
carries the device's hashed user secrets, so it must never sit inside the
repo tree (INV-001). Restore is a whole-config replace (`eos_config
replace: config`) verified by comparing the restored snapshot against the
backup. A wave that failed before the backup reports that no change was made.
