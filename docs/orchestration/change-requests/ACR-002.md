# ACR-002 — Remove vault_password_file from committed config

Status: accepted. Baseline: v1 (amendment, not a baseline change).
Date: 2026-09-21. Raised by: ORCHESTRATOR during T-005 V1.

## Context
T-005 V1 (ci_gate) failed its own secret scan: `ansible.cfg` named a local
vault password filename (T-000). The value was a filename, not a secret, but committed config must not name secret-material locations: the
scanner cannot distinguish a benign filename from a leaked path, and every
exception weakens the fail-closed posture (INV-001).

## Decision
Delete the line from `ansible.cfg`; replace with a comment pointing at
runtime-only provisioning (`--vault-password-file` flag or
`ANSIBLE_VAULT_PASSWORD_FILE` in the operator environment). `.gitignore`
keeps ignoring `.vault_pass` for operators who use that filename locally.

## Impact
Amends one T-000-owned file. Live behavior: operators pass the flag as
before; nothing in roles/playbooks referenced the cfg value. T-000 stays
historical truth; this record is the authorization.

## Rollback
Restore the line and add a scanner allowlist (rejected: weaker posture).
