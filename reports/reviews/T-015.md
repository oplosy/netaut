# Review — T-012..T-015 (SR Linux live lab, backup, restore)

Reviewer: REVIEW_AGENT — fresh-context subagent (Opus), whole-branch review of
feat/srlinux-live-lab (e70b655..a2f02a1) against the plan, the spec, ADR-005/-007
and the plan's Review Focus. It doubles as the mandatory HIGH review for T-015.
Date: 2026-09-23. Verdict before fixes: "with fixes".

## Findings fixed on the branch (21a74fa, each RED -> GREEN)
1. CRITICAL, pre-existing since T-004, affects every vendor. `drift.py` never
   reported an intended interface that the device does not report, so a
   tagged, routed or detached SR Linux port (which the parser correctly
   leaves out) passed the post-check and no restore ran. Drift now records
   "intended interface X missing operationally". Tests:
   test_intended_interface_missing_operationally_is_drift,
   test_tagged_routed_or_detached_port_fails_the_post_check (parser + drift, rc 2).
2. IMPORTANT. The post-check wrote the snapshot over the fetched running
   datastore (`<host>-post.json` for both on srlinux). The fetch is now
   `<host>-post-running.<ext>`. Test:
   test_postcheck_keeps_the_raw_fetch_apart_from_the_snapshot (resolves the
   per-vendor extension; the first version passed vacuously and was fixed first).
3. IMPORTANT. `--compare` stripped YANG prefixes before the equality check, so
   same-named keys from two modules or a value change inside a prefix-shaped
   string could hide a difference. Equality is now on the raw documents; only
   printed names are stripped. Test:
   test_compare_sees_differences_that_prefix_stripping_would_hide.
4. IMPORTANT (part). A failed drill still ran the deploy and rerun waves on a
   lab in an unknown state. lab-verify now stops after a failed drill and names
   the hosts without "restore verified". Test:
   test_failed_drill_stops_before_deploy_and_names_the_hosts.
5. IMPORTANT. A mixed port (untagged .0 plus tagged subinterfaces) or an
   untagged member on another index counted as a clean access port. Only an
   interface whose sole subinterface is untagged, bridged .0 counts now. Test:
   test_mixed_or_non_zero_index_port_is_not_an_access_port.

## Ruled, not changed
- Readiness is TCP on 443, not a JSON-RPC call: during planning SR Linux opened
  443 only after its startup commit, and an app-level probe would need vault
  credentials inside lab_verify. Cost if wrong: a slow node fails the drill
  with a named host instead of a clean "not ready" line.

## Minors (deferred in #6, fixed in the follow-up PR, each test-first)
1. `make lab-vault` echoed the lab login: now passed by environment, line not
   echoed, removed from T-013 evidence (test_lab_login_travels_by_environment_and_is_not_echoed).
2. A wave id was reusable across vendors: the backup check matches any
   extension (test_wave_id_is_unique_across_vendor_extensions).
3. The parser could print a traceback: any failure is now the error type only,
   rc 1 (test_malformed_document_is_a_clean_error).
4. A failed srlinux restore gave no diagnostics: the backup is parsed first in
   a logged, secret-free step (test_srlinux_restore_checks_the_backup_before_replacing).
5. `lab-cycle` left containers up when bring-up failed; unknown `LAB=` was
   unclear: both fixed (test_lab_cycle_tears_down_even_when_bring_up_fails,
   test_unknown_lab_stops_with_a_clear_message).
6. Braces were only tested on restore: backup and fetch are now pinned too
   (test_srlinux_backup_and_fetch_write_braces_verbatim, fake `nokia.srlinux.get`).
7. The T-015 restore-proof block is generated by a script and labelled as such.
8. EOS lab users: default lab is now srlinux, EOS vault moved to
   `lab-vault-eos.yml` (documented in CHANGELOG v1.1.0 and README).
